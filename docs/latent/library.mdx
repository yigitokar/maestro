`@filmsim/spectral-data` is Latent's library: 51 film stocks, 12 scanners and print stocks, and 32 looks. Every profile is validated when the package is first imported, so a broken profile fails at start-up, not in the middle of a render.

A **stock** is the film: how it responds to light, its grain and its halation. A **scanner** is what turns the negative or slide back into a picture: a lab scanner, a camera scan, a print film or a photographic paper. A **look** names a stock, a scanner and the parameters of one recipe, such as a film pushed two stops.

## List and look up

```ts
import { LOOKS, SCANNERS, STOCKS, findStock, getScanner, getStock } from "@filmsim/spectral-data";

STOCKS.length; // 51, always in the same order
const portra = getStock("kodak_portra_400"); // throws "Unknown film stock: ..." for an unknown id
const maybe = findStock(idFromTheUrl); // undefined for an unknown id
const frontier = getScanner("fuji_frontier_sp3000");
```

`getScanner()` and `getLook()` throw in the same way, and `findScanner()` and `findLook()` return `undefined`. Use the `find` functions for ids that come from outside your code, such as a URL or saved settings.

`DEFAULT_STOCK_ID` is `"kodak_gold_200"` and `DEFAULT_SCANNER_ID` is `"fuji_frontier_sp3000"`.

## Group stocks for a picker

```ts
import { STOCKS, STOCK_CATEGORIES, stockCategory } from "@filmsim/spectral-data";

for (const category of STOCK_CATEGORIES) {
  const stocks = STOCKS.filter((stock) => stockCategory(stock) === category.id);
  // category.label is "Colour negative", "Cinema", "Black and white" or "Slide"
}
```

Each stock also carries what a picker can show. `name` and `iso` are always there. `manufacturer`, `description`, `tags`, `balance` and `fidelity` are optional in the type, and every stock in the library has them. `year` and `discontinued` are set on some stocks only.

`stockTraits(stock)` returns four numbers from 0 to 1 for small meters next to a stock: `contrast`, `saturation`, `grain` and `halation`. They compare stocks with each other. They are not measurements.

## Apply a look

```ts
import { getLook, getScanner, getStock, lookToParams } from "@filmsim/spectral-data";

const look = getLook("cinestill_800t_night_streets");
pipeline.setProfiles(getStock(look.stockId), getScanner(look.scannerId));
pipeline.setParams(lookToParams(look));
pipeline.render();
```

A look stores only the parameters it changes. `lookToParams(look)` fills in the rest from the defaults and returns complete parameters. Pass a second argument to keep some of the current settings under the look:

```ts
const params = lookToParams(look, { grainSeed: current.grainSeed });
```

The order is: defaults, then your second argument, then the look.

## Render thumbnails

`renderVariant()` renders the current photo through another look at a small size, without disturbing the preview. It resolves with an `ImageData` whose long edge is the size you ask for.

```ts
for (const stock of STOCKS) {
  const image = await pipeline.renderVariant({ stock, scanner, params: { ...params, stockId: stock.id } }, 144);
  const thumbnail = document.createElement("canvas");
  thumbnail.width = image.width;
  thumbnail.height = image.height;
  thumbnail.getContext("2d")?.putImageData(image, 0, 0);
  list.append(thumbnail);
}
```

Render them one after another, as here. In a long list, render the visible ones first and cache the results: the Latent app does both in its own code, outside the packages.

## Compute a swatch without a GPU

`shadePixel()` in `@filmsim/core-types` develops one pixel of a uniform color on the CPU. It is exact for a flat patch, where halation has nothing to spread, and it is cheap enough for color swatches.

```ts
import { DEFAULT_PARAMS, deriveRuntime, shadePixel } from "@filmsim/core-types";

const runtime = deriveRuntime(stock, scanner, { ...DEFAULT_PARAMS, grainScale: 0 }, { widthPx: 3000, heightPx: 2000 });
const { display } = shadePixel(runtime, [0.5, 0.5, 0.5]);
// display is the finished color: sRGB-encoded [r, g, b], each from 0 to 1
```

The input color is sRGB-encoded too. This also runs in Node.

## Use a profile of your own

`setProfiles()` accepts any object of the profile types, not only the library's. Validate yours first:

```ts
import { parseFilmStock } from "@filmsim/core-types";

const stock = parseFilmStock(await (await fetch("/my-stock.json")).json());
pipeline.setProfiles(stock, scanner);
```

`parseFilmStock()` and `parseScanner()` throw a `ZodError` that names the field when the object does not fit. They check more than types: curve points must rise in exposure, for example.

To start from an existing profile, import its JSON file from the package:

```ts
import gold from "@filmsim/spectral-data/profiles/stocks/kodak_gold_200.json";
```

In TypeScript this needs `resolveJsonModule`. Scanners are under `profiles/scanners/` and looks under `profiles/looks/`. [Where the profiles come from](/latent/profiles) explains the fields.
